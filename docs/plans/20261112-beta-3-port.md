# DWTC-352: port beta-2 from waste-movement-backend as beta-3

## Goal

Serve the Phase 2 waste movement journey from this service as `beta-3`, starting from a copy of
`waste-movement-backend`'s `beta-2` (routes, JSON Schemas, OpenAPI spec, data access, unit and
integration tests). No Phase 1 (Receipt of Waste) endpoints, no beta-1.

## Decisions

- **One folder per version.** Everything specific to a version lives in `src/versions/<version>/`.
  A new version is `cp -r` of the folder plus one router line; retiring one is deleting the folder
  and that line.
- **Generic machinery is shared** in `src/common/` (validator, error mapping, HTTP client,
  versioned collections, route errors, organisation header, `$ref` resolver). Contract-specific
  code (routes, schemas, spec, checks, data access) stays in the version folder.
- **Explicit router registration**, one line per version, rather than auto-discovering folders.
- **Persistence is beta-2's**, unchanged in shape. Collections are named
  `<version>-r<DATA_REVISION>-<name>`, e.g. `beta-3-r1-movements`.
- **Reset on shape change is manual**: bump `DATA_REVISION` when the stored shape changes. No
  shape hash or record-schema check. On boot, a sweep drops this version's collections for any
  other revision.
- **Unique index on `movementId`** (non-unique on `deliveryId`, since a resubmitted hazardous
  movement has more than one delivery record). A duplicate key on a backoff retry is treated as
  success.
- **Tests are ported as-is** (Jest → Vitest, same structure). Vitest fixtures are a follow-up.
- **Bundled OpenAPI endpoint is a follow-up**, but the `$ref` resolver moves to `src/common/` now.

## Steps

### 1. Shared validation and openapi resolver

- [ ] Port `src/schemas/validate/{index,hapi-validator,payload-checks}.js` to
      `src/common/validation/`, parameterised by schema root instead of a version string
      (`createValidators(import.meta.dirname)`).
- [ ] Port their tests (`jest.*` → `vi.*`), pointing at a small fixture schema root.
- [ ] Extract the `$ref` resolver from `src/schemas/openapi-betas.test.js` into
      `src/common/openapi/bundle.js` with its own test.
- [ ] Add deps `ajv`, `ajv-formats` (already present), `exponential-backoff` (present),
      `@defra/waste-movement-utils` (bump to 1.21.0, matching the backend). Check every added or
      bumped version with `npm view <pkg> time` (7-day minimum release age).

### 2. Shared runtime pieces

- [ ] `src/common/http/`: the waste-tracking-id client on `@hapi/wreck`, replacing the old
      `http-client.js`; `createMovementId` / `createDeliveryId`.
- [ ] `src/common/organisation.js`: `getOrganisationId`, `ORGANISATION_ID_HEADER`, and the
      `ValidationError` it throws.
- [ ] `src/common/route-errors.js`: `handleBetaRouteError` without the Mongo document-validation
      and bulk-warning branches.
- [ ] `src/common/data/`: `versionedCollections(apiVersion, revision)` (name builder) and
      `sweepStaleRevisions(db, apiVersion, revision)` (drop `^<version>-r(\d+)-` where N ≠
      revision, log each drop, ignore `NamespaceNotFound`).
- [ ] Tests for each, sweep test against in-memory Mongo: drops `beta-3-r0-*`, keeps
      `beta-3-r1-*` and `beta-4-*`.

### 3. Server wiring and config
